Ports & Adapters

Hexagonal Architecture

คิดค้นโดย Alistair Cockburn (~2005) — โฟกัสที่ "ขอบ" ของระบบ core คุยกับโลกภายนอกผ่าน Port (สัญญา) และ Adapter (ตัว implement)

  • Driving side (ซ้าย/บน) — ใครเรียกเรา: REST, CLI, Test
  • Driven side (ขวา/ล่าง) — เราเรียกใคร: DB, Email, Queue
  • เปลี่ยน adapter ได้อิสระ core ไม่รู้เรื่อง
  • ไม่บังคับจำนวนชั้นภายใน — ยืดหยุ่นสูง

💡 ลองชี้ที่ adapter แต่ละตัวในรูป แล้วดู data flow วิ่ง

Concentric Layers

Clean Architecture

คิดค้นโดย Robert C. Martin (Uncle Bob) (~2012) — รวม Hexagonal + Onion + DDD เป็น 4 ชั้นซ้อนเป็นวงกลม มี Dependency Rule ที่เข้มงวด

  • Entities — enterprise business rules (ในสุด)
  • Use Cases — application business rules
  • Interface Adapters — Controller, Presenter, Gateway
  • Frameworks & Drivers — DB, Web, UI (นอกสุด)

💡 คลิกแต่ละวงเพื่อดูรายละเอียด — สังเกตลูกศรชี้เข้าด้านในเสมอ

Dependency Rule ชั้นในห้ามรู้จักชั้นนอก — คลิกวงเพื่อสำรวจ

Hexagonal vs Clean

ประเด็น ⬡ Hexagonal ◎ Clean
มุมมองหลักขอบเขต in/outชั้นซ้อนเป็นวง
โครงสร้างcore + ports + adapters (แบน)4 ชั้นชัดเจน
ความละเอียดที่กำหนดน้อย — ยืดหยุ่นมาก — opinionated
คำศัพท์เด่นPort, Adapter, Driving/DrivenEntity, Use Case, Presenter
เส้นโค้งการเรียนรู้เบากว่า เริ่มง่ายมีกฎเยอะกว่า
เหมาะกับเริ่มเบาๆ ปรับเองทีมใหญ่ อยากมีแบบแผนชัด

“Clean Architecture คือการ รวม Hexagonal, Onion, DCI, BCE เข้าด้วยกัน” — Robert C. Martin · มองได้ว่า Clean เป็น superset ของ Hexagonal
